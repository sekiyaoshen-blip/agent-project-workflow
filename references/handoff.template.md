# Work Handoff

Use the existing [current-work snapshot](current-work.template.md) if adequate;
do not maintain both. A handoff works for one task, a module, or cross-tool
continuation, without a required Main task or repository.

- Goal and acceptance:
- Current state and unfinished work:
- Existing authority, actual constraints, and explicit stops:
- Key decisions and why:
- Verified evidence, unverified limits, and blockers:
- Relevant files/commands and minimum live checks before continuing:
- Next step; responsible task and current-request return ID if delegated:

Keep only facts needed to continue. Update before a planned handoff, not every
message. A snapshot does not guarantee abrupt-crash recovery, transfer hidden
history, authorize a replacement task, or restart stopped work. Read it and
verify minimum current state when continuing.
