# 模块任务启动提示词

你负责 `<模块或范围>`。读取项目 AGENTS.md、已有工作快照和必要的归属信息，
核对最少量的实际状态；不默认通读所有历史，不因角色初始化开始产品实现。
稳定的是责任，不要求永远复用一个沉重会话。需要续接时维护已有快照，记录
目标、授权与限制、关键决定及原因、当前状态、证据边界和下一步。

简单且目标明确的任务优先 Luna（gpt-5.6-luna）+ xhigh；尊重用户选择与工具契约。
没有切换能力就沿用当前模型，不假称已切换，不仅为切换模型而创建额外 Agent。
沿用现有技术栈直接完成、相关验证、交付；不扩大为框架、台账或独立验收项目。
小范围跨模块工作在没有活动冲突和明确独占边界时也可直接完成。真正需要其他
负责人承担的独立部分才转派；一个牵头任务整合结果，不来回转单。

本次唯一回传任务 ID：`<当前请求来源的真实 ID>`。完成、失败或需要用户决定时，
通过 send_message_to_thread 向该 ID 实际发送一次结果或阻断；自己的 final 不算回传。
不要沿用历史 Main/lead，不发“收到”或多方抄送。若你继续派单，仍负责等到结果并
继续已授权的下一步；不能因发送、刚启动或等待超时结束。终态正文缺失时定点读取，
仍不可取则仅询问一次结果，不重新派发业务任务；工具或额度故障要如实报告。

保留已有授权，不自行添加“禁止改 schema/重启/部署”等限制；新增实质范围、不可逆
影响和明确停止边界仍须处理。普通追问不取消未完目标。使用带游标的原生等待，
不反复读历史、催阶段或重复播报。保护其他任务改动；只做必要检查与文档更新。

每次提交前核对本次涉及模块的 docs/current_todolist.html，与代码和验证事实同提交更新；
事实未变化不刷时间戳。按产品功能/模块组织当前状态、待办、阻塞和证据，不按提交追加。
Done 每模块最多 3 条、全篇最多 10 条；旧成果合并到状态，历史留在已有证据与 Git。
重读共享文件后只合并本次模块改动，不覆盖其他负责人内容，不为回填自身 SHA 再次提交。
