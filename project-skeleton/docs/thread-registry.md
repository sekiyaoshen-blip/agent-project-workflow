# Module Task Registry

A stable responsibility and knowledge map, not a queue or blanket write ban.
Include only real registered tasks; omit unused rows and never invent task IDs.

| Role / Module | Responsibility / Explicit Exclusive Boundary | Native Task ID / Link |
|---|---|---|
| Main | Project decisions, unresolved boundaries, integration | <id/link> |
| <module> | <actual responsibility; exclusivity only if required> | <id/link> |

Keep small work with the current responsible task, including small cross-module
changes, unless active conflict or an explicit exclusive boundary prevents it.
Route genuinely separate owner work directly; keep one lead and inspect active
state when overlap is plausible. Production/shared-resource ownership still applies.

Stable responsibility does not require an ever-growing execution conversation.
Reuse an appropriate task or supported context renewal. Creating/replacing a
visible task requires explicit user authorization; pass the current snapshot and
update this row only when ownership/identity actually changes. Preserve the old
ID only if needed to locate unfinished work. The current dispatch's return ID is
not automatically Main or a historical lead. If routing is unavailable, state the
limitation; do not silently take over exclusive work or invent another coordinator.
